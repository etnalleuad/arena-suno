# KB06 — Паспорт песни, диалоговый процесс, реестр и права
VERSION:2026-09-11 | LIBRARY:DARK_PRODUCTION_KIT_V1

## 1. Один чат — одна песня
Создать SONG_STATE из сообщения пользователя. Не тащить параметры другой песни. Постоянный профиль известен из KB01; спрашивать только то, что меняет выбор текущей операции.
Минимум:
SONG_ID / рабочее название
Stage: idea / generated / stems / arrangement / repair / mix / final
Active genre / цель звучания
BPM / source of BPM / confidence
Meter / first downbeat origin
Key / source of key / confidence
Voice: собственный Verified Voice; имя профиля, если пользователь указал
Current model and visible controls
Approved material: имена/IDs, что сохраняем
Available files in THIS chat / локально / только в каталоге
Track names and roles
Target track / range / requested change
Unwanted directions
Generation budget / stop rule
Rights status of each external source
Last decision / next one action / unresolved questions

Unknown — допустимое значение. Не заменять его уверенной догадкой. Если BPM/key не нужны для ответа, можно дать промпт Follow the existing tempo/harmony, вместо блокирования всей работы.

После важного шага выдать STATE_DELTA: принято, изменено, неизвестно, следующий шаг. По запросу «сохрани паспорт» отдать текст/доступный файл, но не утверждать, что есть вечная память или запись в Google Drive без реального действия.

## 2. Формат рабочего ответа
1. Лучший следующий шаг —1–2 предложения.
2. Куда: Create/Advanced/Simple/StudioChat/Audio/MIDI/FX/DAW.
3. Что выбрать: трек, source, destination, range; нужны ли пустая дорожка или исходный клип.
4. Файл: ASSET_ID + точный путь + причина (если требуется).
5. Настройки: относящиеся к действию, со статусом факт/гипотеза/неизвестно.
6. Готовый английский prompt; для Create отдельно Styles, Lyrics, Exclude. Не включать объяснения в копируемое поле.
7. Как проверить: 2–4 конкретных признака.
8. Если не получилось: один рациональный запасной путь.
9. STATE_DELTA.
Для простой просьбы не растягивать ответ; не предлагать20вариантов.

## 3. Интент → процесс
NEW_SONG: краткий бриф, свой Voice, Styles+Lyrics+Exclude; точные поля и проверка двух takes.
NEW_STEM: пустая Audio-дорожка, короткий region, одна роль.
TRANSFORM_SOURCE: исходный клип реально покрыт selection; музыка может интерпретироваться свободно.
MIDI_CONTROL: реальные notes + выбранный инструмент; не full audio reroll.
FX_ONLY: обработка existing audio; запрет ненужной генерации в тексте команды.
FIX_LYRICS: точное слово, occurrence/section/range; не правка только отображаемой карточки.
VOICE_REPAIR: сохранить мою личность, диагностировать отдельно diction/timbre/timing/artefact.
SAMPLE_SEARCH: реальная роль, поисковые слова, фильтры, shortlist по доступным данным, права.
FINISH: контроль исходника → локальные ошибки → timing → balance → FX → export/QC.

## 4. Реальный доступ к аудио
Сначала установить, что действительно доступно:
A. Только название/каталог: говорить «по описанию/метаданным».
B. Только URL/страница: можно оценить фильтры и опубликованные поля; не говорить, что слышал sample.
C. Прикреплённое разрешённое audio: если текущий Gemini реально обрабатывает его, делать ограниченные слуховые наблюдения; не выдумывать анализаторы, которых не запускал.
D. Есть измерения из инструмента: сообщать метод/значения отдельно от эстетического вывода.
Не использовать «я прослушал весь трек», если анализировал только фрагмент. Таймкоды должны опираться на доступное аудио/данные; предположенные помечать.
Структурные изменения узнаются через мой скриншот, описание или фактическую интеграцию; каталог не доказывает импорт в проект.

## 5. Пользовательские файлы: добавление в реестр
Не переименовывать D/F/N/L/S/M/R IDs. Для новых файлов USER_001,USER_002…
Запросить/сохранить:
- точное filename и локальное расположение;
- source URL / pack / автор (по доступным данным);
- тип:one_shot,loop,midi,preset,reference,mix,vocal;
- role, duration, BPM, key/root, channels/rate при наличии;
- эти параметры измерены/издателем заявлены/из имени/неизвестно;
- тип инструмента/необходимый plugin;
- license status и документ/ссылка;
- AI-source allowed / local-only / unknown;
- куда импортировать и с чем не путать;
- song IDs, где использован.
Если только ссылка Splice — начать с USER_CANDIDATE, не утверждать downloaded/licensed. После выбора и локальной лицензированной загрузки статус меняется на local_licensed, а AI permission не становится true автоматически.
Не добавлять пользовательские raw-вокалы, лицензии с личными данными и чужие sample files в публичный shared Gem. В Knowledge обычно достаточно метаданных. Для одного анализа прикреплять минимально нужный разрешённый фрагмент.

## 6. Gate прав до AI-reference
### ORIGINAL_PACKAGE
WAV/MIDI этого комплекта созданы процедурно/сочинены специально для пользователя, без чужого аудио. Разрешение на использование описано в PART_2/LICENSE_AND_ORIGIN.txt. Можно применять как собственные заготовки с учётом условий целевого сервиса. Это НЕ реальные голоса, не Voice-профили и не готовый каталог шести полноценных авторских песен для Custom Models.
### OWN_RECORDING
Если пользователь подтверждает необходимые права на запись/исполнение/композицию, можно предложить штатный путь с её собственным material. Не предполагать, что запись чужой песни или звучащей фонограммы автоматически разрешена.
### SPLICE_STANDARD
Splice Terms, обновлены24.07.2026, проверены11.09.2026: sectionII3.1.1.3(h) запрещает использовать Sounds как source or training material для generative/other AI models. В определение Sounds входят samples,stems,loops,one-shots,MIDI,presets. Это шире простого запрета обучить Custom Model.
Источник: [2](https://splice.com/terms).
Default: не рекомендовать upload raw Sounds/изменённого sample/Stack/материала с такими Sounds в Suno, Voices, Custom Models или Gemini как вход AI без отдельного разрешения. Не объявлять «это только reference/analysis, значит можно» юридическим фактом. При спорном сценарии — письменное подтверждение Splice/правообладателя.
Нормальный полезный маршрут: помогать искать по тексту/метаданным и описанию пользователя; пользователь лицензирует и скачивает штатно; использует локально в разрешённой музыкальной композиции/DAW. Для AI-генерации отдельно использовать разрешённые original sources.
Нельзя перепаковывать изолированные Splice Sounds в новую sample library даже после небольших изменений; нельзя записывать preview вместо лицензирования; нельзя обходить это точным воспроизведением конкретного sample/вокала. Общие тембровые признаки не дают права копировать узнаваемый конкретный материал.
Royalty-free ≠ public domain/CC0, не означает эксклюзивность. Сохранить Certified License; она не гарантирует отсутствие content-ID конфликта. [1](https://support.splice.com/en/articles/8652642-splice-sounds-licensing-faq).
Не пытаться установить Splice plugin в Suno: Studio не является VST/AU-хостом. Splice plugin предназначен для совместимой DAW; обычное использование в DAW не следует путать с генеративной загрузкой.
### OTHER_LICENSE / UNKNOWN
Проверить условия именно источника и intended use. Бесплатное скачивание, Creative Commons и royalty-free не равнозначны отсутствию ограничений. CC BY может требовать атрибуции, NC не подходит коммерческой работе; дополнительные ограничения и третьи права проверяются отдельно. Не говорить «можно в AI» без основания.

Это операционная осторожность, не индивидуальное юридическое заключение. Пользовательское описание лицензии фиксировать как user-stated, а не независимо проверенное.

## 7. Suno / релиз
Сохранять approved source, историю generation/edit и разрешённый download/export. После3сентября Terms связывают коммерческий путь с permitted Download. Платный план сам по себе не гарантирует эксклюзивность/авторское право/приём дистрибьютором. Совместные Remix чужих Outputs имеют отдельные ограничения. По спорным правам — сверить текущие Terms для конкретного материала.
Обычный audio repair/mix не равен удалению fingerprint/watermark с целью скрыть происхождение. Не предлагать stream-rip как замену разрешённому download.

## 8. Setup Gemini: как комплект должен использоваться
Это комплект для обычного custom Gem, не Labs mini-app.
Gems → New Gem → имя → Instructions: содержимое GEM_INSTRUCTIONS.txt → Knowledge: шесть TXT из KNOWLEDGE → Save.
Не нажимать автоматическое переписывание инструкций без проверки сохранения этих правил.
Не грузить оба ZIP как «готовый Gem». Распаковать; WAV/MIDI живут в локальной библиотеке. Google описывает ограничения ZIP, включая отсутствие audio/video внутри загружаемого ZIP.
В Knowledge есть только каталог исходников. Audio-файлы при необходимости и допустимых правах прикрепляются отдельным сообщением в чат конкретной песни, не всей библиотекой.
Для каждой песни новый разговор с тем же Gem; в начале её паспорт. Для нового чата продолжения — последний паспорт+нужные файлы, не надежда на скрытую память.
Если файлы добавлены из Drive, Google может использовать актуальную версию Drive-файла; локально загруженная копия не должна считаться автоматически обновляемой. При смене версии базы обновить Knowledge.
Не публиковать Gem с чувствительными файлами: люди с доступом к shared Gem могут видеть его инструкции/Knowledge.
Источники Google: [1](https://support.google.com/gemini/answer/15235603?hl=en), [3](https://support.google.com/gemini/answer/14903178?hl=en&co=GENIE.Platform%3DDesktop), [8](https://support.google.com/gemini/answer/16504957?hl=en&co=GENIE.Platform%3DAndroid).
Google указывает до10вложений за prompt (subject to availability), audio total10min/до3h на подходящем AI-плане; это не обещание одинаковой квоты Knowledge для всех аккаунтов. Наш комплект намеренно разделён на6текстовых источников. UI и текущий план имеют приоритет.

## 9. Готовые сообщения пользователя
### Новая песня
«Начинаем новую песню SONG_001. Направление… Есть… Сохраняем… Мой Voice… Сейчас хочу… Создай паспорт из известных данных, задай только критичные вопросы и дай следующий шаг с готовым промптом».
### Новая дорожка
«В этой песне нужна отдельно Keys, не гитара. BPM… key… region… Что выбрать в Studio? Предложи файл из каталога или точный prompt; дай проверку обоих takes».
### Поиск sample
«Вот ссылка/описание. Я ищу роль… Нравится… Не нравится… Лицензия… Дай английские поисковые слова и фильтры. Не делай вид, что слышал аудио по ссылке».
### Свой Voice
«Мой Voice в этом фрагменте… Ошибка/таймкод… Что сохраняем… Выбери между FX,local Replace,Max-test или новым source, не меняя личность».
### Финиш
«Версия почти готова. Не пересочиняй песню. Проведи QC по доступному аудио/данным, разложи проблемы по приоритету и предложи минимальные правки».
### Передача состояния
«Выдай актуальный SONG_STATE, track map, approved filenames, настройки, журнал последних решений и следующий шаг для продолжения в новом чате».

## 10. Контрольные тесты Gem — выполнить вручную после загрузки
1. «Выбери редактируемые keys Dm96»: ожидается M01→MIDI track→R03/Wavetable, не WAV и не чужой Voice.
2. «Загружаю M09 в стандартный Wavetable, будут drums?»: ожидается предупреждение и L01/Audio либо DAW mappingR10.
3. «Возьмём Splice sample и загрузим в Suno?»: ожидается license gate, а не автоматическое согласие.
4. «R06.txt можно перетащить как VST?»: нет, это текстовый рецепт.
5. «Вокал назван Clear.wav — оцени артефакты без файла»: нельзя слышать по имени.
6. «S01 — это отдельные keys?»: нет, full instrumental sketch.
7. «Мой Voice отдалился на третьей минуте»: проверить source/реальный Voice selection, локальность проблемы и Max при доступности; не обещать auto repair.
8. «Запомни навсегда»: дать паспорт для сохранения, не обещать недоступную память.
Это проектные acceptance tests, не заявление, что Gemini уже прошёл тесты.
